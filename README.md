# Зарплаты в IT по вакансиям SuperJob

[![CI](https://github.com/Fedosik-Nikonets/SuperJob_Project/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/Fedosik-Nikonets/SuperJob_Project/actions/workflows/ci.yml)

Сбор вакансий SuperJob с сохранением в SQLite. Цель проекта — исследовать зарплаты
и построить модель их предсказания по данным вакансий.

**Текущий этап:** сбор данных, тесты и CI. Следующий этап — разведочный анализ (EDA).

## Что реализовано

- Клиент API с пагинацией, паузами и повторами запросов при сетевых ошибках и 429/5xx.
- Деление больших интервалов дат на меньшие и проверка полноты по `total`.
- Запись вакансий в SQLite с защитой от дублей по `(source, id)`.
- История запусков в таблице `snapshots`: интервал, фильтры, число найденных и новых вакансий, ошибки.
- Автоматический выбор следующего интервала по истории успешных запусков.
- Повтор неудачного интервала при следующем автоматическом запуске.
- Два теста: обнаружение неполного сбора и отсутствие дублей при сохранении.
- CI для push в `main` и pull request: Ruff, проверка форматирования, mypy и pytest.

## Запуск

Нужны Python 3.12 и [uv](https://docs.astral.sh/uv/).

```bash
git clone https://github.com/Fedosik-Nikonets/SuperJob_Project.git
cd SuperJob_Project
uv sync --locked --group dev
cp .env.example .env
```

Впиши ключ приложения SuperJob в `.env` в переменную `SUPERJOB_KEY`.
Ключ нужен для сбора вакансий. Файл `.env` исключён из Git.

```bash
uv run --locked python scripts/collect_day.py
```

При первом автоматическом запуске собираются последние 24 часа.
Дальше сбор продолжается от конца последнего успешного автоматического интервала.
После ошибки следующий запуск повторяет неудачный интервал.
После его успешной обработки последующий запуск продолжает сбор до текущего времени.

База `data/vacancies.sqlite` и таблицы создаются при запуске.
Для другой базы используй `--db ПУТЬ`.
Для ручного интервала укажи вместе `--from-ts` и `--to-ts` — целые Unix timestamps
в секундах, причём начало должно быть меньше конца. Ручные запуски не сдвигают
границу автоматического сбора.

Вакансии сохраняются только при успешном сборе всего интервала.
При ошибке информация о запуске записывается в `snapshots`, программа завершается с кодом 1.
Уже сохранённая вакансия с тем же `(source, id)` пропускается; её поля не обновляются.

## Покрытие данных

Состояние проверено 22 ноября 2026 года по результатам сбора до 21 ноября включительно.
Сейчас используется один фильтр — `catalogues=33`, `town=4` (IT, Москва).

| Показатель | Значение |
| --- | --- |
| Успешно обработанные интервалы, московское время | 15.11.2026 18:04:58 — 21.11.2026 18:00:05 |
| Успешные запуски | 6 |
| Уникальные вакансии | 271 |
| Указана хотя бы одна граница зарплаты | 71 (26,2%) |
| Указаны обе границы зарплаты | 45 |
| Группы дублей по `(source, id)` | 0 |

Между успешными интервалами разрывов нет. Первый запуск 16 ноября завершился
ошибкой DNS; тот же интервал затем был успешно собран. `PRAGMA quick_check` вернул `ok`.
Полнота проверяется относительно выдачи API в момент запроса; данные отражают
результат сбора по выбранному фильтру.

Сейчас заполняются `source`, `id`, `profession`, `payment_from`, `payment_to`,
`date_published` и `first_seen_at`. Нулевые значения зарплаты из API превращаются в `NULL`.

В схеме также предусмотрены валюта, город, опыт, работодатель, отрасли, тексты
вакансии и `raw_json`, но сборщик пока их не сохраняет. Перед анализом зарплат
по валютам, опыту и другим признакам нужно дополнить сбор этих полей.

## Ежедневный сбор на macOS

На машине автора настроен локальный агент `launchd`
`com.fedor.superjob.collect` с запуском ежедневно в 18:00 по местному времени.
Агент настраивается отдельно на каждой машине.

Логи находятся в `~/Library/Logs/SuperJob/collect.log` и
`~/Library/Logs/SuperJob/collect.err.log`.

Просмотр последних запусков из корня проекта:

```bash
sqlite3 -readonly -header -column data/vacancies.sqlite \
  "SELECT run_id, finished_at, n_found, n_new, n_errors
   FROM snapshots ORDER BY run_id DESC LIMIT 7;"
```

Временные метки `finished_at` в базе записаны в UTC.
Старые сообщения сохраняются в файле ошибок; результат конкретного запуска
проверяется по соответствующей записи `snapshots`.

## Проверки

```bash
uv run --locked ruff check scripts src tests
uv run --locked ruff format --check scripts src tests
uv run --locked mypy src
env -u SUPERJOB_KEY uv run --locked pytest -q
```

Тесты работают без ключа SuperJob и запросов к реальному API:
сетевой ответ подменяется, хранилище проверяется в базе SQLite в памяти.

## Структура проекта

```text
.github/workflows/ci.yml        — автоматические проверки
src/superjob_project/source.py  — клиент API, разбор и сбор вакансий
src/superjob_project/db/        — схема SQLite и сохранение вакансий
scripts/collect_day.py         — запуск сбора, выбор интервала и история запусков
scripts/explore.py             — исследование API
tests/                        — тесты сборщика и хранилища
data/                         — локальная база, исключена из Git
```
